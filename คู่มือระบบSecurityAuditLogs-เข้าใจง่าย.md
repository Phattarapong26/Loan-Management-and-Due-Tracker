## 1. ระบบความปลอดภัยคืออะไร

### 💡 อธิบายง่ายๆ
ระบบความปลอดภัยคือ **"ยามรักษาความปลอดภัยของระบบ"** - คอยดูว่าใครเข้ามา ทำอะไร มีพฤติกรรมแปลกๆ ไหม

### 🛡️ 5 ชั้นความปลอดภัย

```
┌─────────────────────────────────────────────────────────────────┐
│  🧱 ชั้นที่ 1: กำแพงป้องกัน (Perimeter)                        │
│  ────────────────────────────────────────────────────────        │
│  • Rate Limiting: จำกัดจำนวน request/นาที                        │
│  • CORS: ควบคุมว่าใครเรียก API ได้                               │
│  • Helmet Headers: ป้องกัน XSS, Clickjacking                   │
│                                                                 │
│  เปรียบเทียบ: เหมือนรั้วบ้าน + ประตูรั้ว                        │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│  🔐 ชั้นที่ 2: การยืนยันตัวตน (Authentication)                  │
│  ────────────────────────────────────────────────────────        │
│  • JWT Token: บัตรประจำตัวดิจิตอล                               │
│  • Refresh Token: ขอ Token ใหม่เมื่อหมดอายุ                       │
│  • Session: จำสถานะล็อกอิน                                      │
│                                                                 │
│  เปรียบเทียบ: เหมือนบัตรพนักงาน + การตรวจบัตร                  │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│  📝 ชั้นที่ 3: การอนุญาต (Authorization)                         │
│  ────────────────────────────────────────────────────────        │
│  • RBAC: สิทธิ์ตามบทบาท (Officer/Manager/Admin)                  │
│  • Permission: สามารถทำอะไรได้                                   │
│  • Branch Scoping: ดูได้แค่สาขาของตัวเอง                         │
│                                                                 │
│  เปรียบเทียบ: เหมือนสิทธิ์เข้าห้องต่างๆ ในบริษัท                │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│  ✓ ชั้นที่ 4: ตรวจสอบข้อมูลเข้า (Input Validation)              │
│  ────────────────────────────────────────────────────────        │
│  • Zod Schema: ตรวจรูปแบบข้อมูล                                │
│  • SQL Injection: ป้องกันการแทรกโค้ดอันตราย                       │
│  • XSS: ป้องกัน JavaScript อันตราย                              │
│  • File Upload: ตรวจไฟล์ที่อัปโหลด                               │
│                                                                 │
│  เปรียบเทียบ: เหมือนเครื่องสแกนของที่ Gate                       │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│  📹 ชั้นที่ 5: บันทึกและตรวจสอบ (Audit & Monitoring)            │
│  ────────────────────────────────────────────────────────        │
│  • Request Log: บันทึกทุกการเข้าใช้                             │
│  • Audit Trail: บันทึกว่าใครทำอะไรกับข้อมูลไหน                  │
│  • Suspicious Detection: ตรวจจับพฤติกรรมแปลกๆ                   │
│                                                                 │
│  เปรียบเทียบ: เหมือนกล้องวงจรปิด + บันทึกเหตุการณ์             │
└─────────────────────────────────────────────────────────────────┘
```

## 2. ระบบบันทึกการใช้งาน (Audit Logs)

### 📋 บันทึกอะไรบ้าง

```
┌─────────────────────────────────────────────────────────────────┐
│  📊 ประเภทบันทึกการใช้งาน                                       │
│                                                                 │
│  1️⃣ Request Audit (บันทึกทุก request)                           │
│     ─────────────────────────────────────                      │
│     • ใคร (User ID)                                             │
│     • ทำอะไร (GET/POST/PUT/DELETE)                              │
│     • ที่ไหน (URL)                                              │
│     • เมื่อไหร่ (Timestamp)                                      │
│     • จาก IP ไหน (IP Address)                                    │
│     • อุปกรณ์อะไร (User Agent)                                   │
│                                                                 │
│     ตัวอย่าง:                                                   │
│     ┌─────────────────────────────────────────────────────────┐  │
│     │ User: somchai@bank.com                                   │  │
│     │ Action: POST /api/loans                                  │  │
│     │ Time: 2026-04-18 14:32:15                               │  │
│     │ IP: 203.131.213.45                                       │  │
│     │ Status: 201 (Created)                                    │  │
│     └─────────────────────────────────────────────────────────┘  │
│                                                                 │
│  2️⃣ Data Access Audit (บันทึกการเข้าถึงข้อมูล)                   │
│     ─────────────────────────────────────                      │
│     • ใครดูข้อมูลลูกค้า                                         │
│     • ดูลูกค้าคนไหน                                             │
│     • ดูอะไร (VIEW/EDIT/DELETE)                                 │
│     • ดูตอนไหน                                                  │
│                                                                 │
│     ตัวอย่าง:                                                   │
│     ┌─────────────────────────────────────────────────────────┐  │
│     │ User: somchai@bank.com                                   │  │
│     │ Customer: บริษัท ABC จำกัด                               │  │
│     │ Action: VIEW (ดูข้อมูล)                                   │  │
│     │ Resource: Loan LN-00152                                   │  │
│     │ Time: 2026-04-18 10:15:30                                 │  │
│     └─────────────────────────────────────────────────────────┘  │
│                                                                 │
│  3️⃣ Invoice Access Audit (บันทึกการเข้าใบเสร็จ)                  │
│     ─────────────────────────────────────                      │
│     • ใครดู/ดาวน์โหลด/พิมพ์ใบเสร็จ                              │
│     • ใบเสร็จของลูกค้าไหน                                        │
│     • ทำอะไร (VIEW/DOWNLOAD/PRINT/EMAIL)                         │
│                                                                 │
│  4️⃣ Suspicious Activity (บันทึกพฤติกรรมน่าสงสัย)                 │
│     ─────────────────────────────────────                      │
│     • พฤติกรรมที่ผิดปกติ                                        │
│     • ความรุนแรง (LOW/MEDIUM/HIGH/CRITICAL)                     │
│     • สถานะ (PENDING/INVESTIGATING/RESOLVED)                     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 🎯 ทำไมต้องมี Audit Logs?

```
✅ ตรวจสอบย้อนหลังได้
   → ใครลบข้อมูลลูกค้าไป?
   → เมื่อไหร่ที่มีการแก้ไขสินเชื่อ?

✅ ความรับผิดชอบ (Accountability)
   → ทุกการกระทำมีคนรับผิดชอบ
   → ป้องกันการโยนความผิด

✅ ตรวจสอบความปลอดภัย
   → มีคนพยายามเข้าระบบผิดพลาดหลายครั้ง?
   → ใครเข้าถึงข้อมูลลูกค้าเยอะผิดปกติ?

✅ ตรงตามกฎหมาย
   → PDPA (พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล)
   → ธนาคารแห่งประเทศไทย
   → สามารถสอบสวนย้อนหลังได้
```

## 3. สิ่งที่ระบบตรวจจับ

### 🚨 Suspicious Activity Detection

```
┌─────────────────────────────────────────────────────────────────┐
│  🔍 การตรวจจับพฤติกรรมน่าสงสัย                                 │
│                                                                 │
│  1️⃣ Velocity Check (ตรวจความถี่)                                │
│     ─────────────────────────────────────                      │
│     ตรวจจับ: ใช้งานระบบถี่เกินไป                                │
│                                                                 │
│     เกณฑ์: > 50 ครั้ง/ชั่วโมง = ผิดปกติ                        │
│                                                                 │
│     ตัวอย่าง:                                                   │
│     ┌─────────────────────────────────────────────────────────┐  │
│     │ ⚠️ ALERT: User somchai@bank.com                         │  │
│     │ เข้าถึงข้อมูล 65 ครั้งใน 1 ชั่วโมง                      │  │
│     │ ปกติเฉลี่ย: 10-15 ครั้ง/ชั่วโมง                        │  │
│     │ ระดับ: MEDIUM                                            │  │
│     │ การกระทำ: ส่งแจ้งเตือน Admin                            │  │
│     └─────────────────────────────────────────────────────────┘  │
│                                                                 │
│  2️⃣ Unusual Pattern (รูปแบบผิดปกติ)                             │
│     ─────────────────────────────────────                      │
│     ตรวจจับ: พฤติกรรมที่ไม่เหมือนปกติ                          │
│                                                                 │
│     • เข้าระบบเวลาแปลก (ตี 3)                                   │
│     • IP Address ที่ไม่เคยใช้                                   │
│     • เข้าข้อมูลลูกค้าที่ไม่ใช่ของตัวเอง                         │
│     • ดาวน์โหลดข้อมูลจำนวนมาก                                   │
│                                                                 │
│  3️⃣ Failed Login Attempts (ล็อกอินผิด)                          │
│     ─────────────────────────────────────                      │
│     ตรวจจับ: พยายามล็อกอินผิดหลายครั้ง                          │
│                                                                 │
│     เกณฑ์: > 5 ครั้ง = บล็อกชั่วคราว                            │
│                                                                 │
│     ตัวอย่าง:                                                   │
│     ┌─────────────────────────────────────────────────────────┐  │
│     │ 🔴 SECURITY ALERT                                        │  │
│     │ ผู้ใช้: somchai@bank.com                                 │  │
│     │ ล็อกอินผิด: 5 ครั้ง                                     │  │
│     │ IP: 171.15.23.45                                         │  │
│     │ สถานะ: บล็อกชั่วคราว 30 นาที                            │  │
│     │ แนะนำ: ตรวจสอบว่าเป็นตัวจริงหรือถูกแฮก                   │  │
│     └─────────────────────────────────────────────────────────┘  │
│                                                                 │
│  4️⃣ Blacklist Match (ตรวจ Blacklist)                           │
│     ─────────────────────────────────────                      │
│     ตรวจจับ: ลูกค้าที่อยู่ในรายชื่อดำ                          │
│                                                                 │
│     • ลูกค้าเข้าเงื่อนไข Blacklist                              │
│     • พนักงานพยายามสร้างสินเชื่อให้ลูกค้า Blacklist             │
│     • การทำธุรกรรมที่น่าสงสัย                                  │
│                                                                 │
│  5️⃣ Data Export (การส่งออกข้อมูล)                               │
│     ─────────────────────────────────────                      │
│     ตรวจจับ: ส่งออกข้อมูลจำนวนมาก                              │
│                                                                 │
│     • Export Excel หลายไฟล์ติดต่อกัน                            │
│     • Print เอกสารจำนวนมาก                                      │
│     • Download ใบเสร็จย้อนหลังหลายราย                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 📊 ระดับความรุนแรง (Severity Levels)

| ระดับ | สี | ความหมาย | ตัวอย่าง | การดำเนินการ |
|-------|-----|---------|---------|--------------|
| **LOW** | 🟢 เขียว | ผิดปกติเล็กน้อย | เข้าระบบนอกเวลาทำงาน | บันทึกไว้ |
| **MEDIUM** | 🟡 เหลือง | น่าสงสัย | Velocity เกิน 50 ครั้ง/ชม. | แจ้งเตือน Admin |
| **HIGH** | 🟠 ส้ม | อันตราย | ล็อกอินผิดหลายครั้ง | บล็อก + แจ้งเตือน |
| **CRITICAL** | 🔴 แดง | วิกฤต | การโจมตีระบบ | ล็อกทันที + แจ้งด่วน |

## 5. ปัญหาความปลอดภัยที่พบบ่อย

### ❌ "ล็อกอินไม่ได้ โดนบล็อก"

**สาเหตุ:**
- ใส่รหัสผ่านผิดเกิน 5 ครั้ง
- ระบบตรวจพบพฤติกรรมน่าสงสัย

**ทำยังไง:**
```
✓ รอ 30 นาที ระบบจะปลดบล็อกอัตโนมัติ
✓ หรือติดต่อ Admin ปลดบล็อกด่วน
✓ เปลี่ยนรหัสผ่านหลังจากเข้าได้
✓ ตรวจสอบว่ามีคนอื่นพยายามล็อกอินหรือไม่
```

---

### ❌ "มีแจ้งเตือน Security Alert ใน Dashboard"

**สาเหตุ:**
- เข้าใช้งานถี่เกินไป (>50 ครั้ง/ชม.)
- IP Address ที่ไม่คุ้นเคย
- ดาวน์โหลดข้อมูลจำนวนมาก

**ทำยังไง:**
```
✓ ตรวจสอบว่าเป็นการกระทำของตัวเองจริงๆ
✓ ถ้าจริง → ไม่ต้องทำอะไร ระบบบันทึกไว้เฉยๆ
✓ ถ้าไม่จริง → แจ้ง Admin ทันที (อาจถูกแฮก)
```

---

### ❌ "ต้องการดูว่าใครแก้ไขข้อมูลลูกค้า"

**สาเหตุ:**
- ข้อมูลลูกค้าถูกแก้ไขโดยไม่ทราบสาเหตุ
- ต้องการตรวจสอบความรับผิดชอบ

**ทำยังไง:**
```
✓ Admin เข้าไปที่ Security Dashboard
✓ เลือก "ตรวจสอบย้อนหลัง"
✓ ค้นหาชื่อลูกค้า
✓ ดูรายการแก้ไขทั้งหมด
✓ ดูว่าใครเป็นคนแก้ไข เมื่อไหร่
```

---

### ❌ "พบว่ามีคนเข้าถึงข้อมูลลูกค้าที่ไม่ใช่ของตัวเอง"

**สาเหตุ:**
- Officer เข้าดูลูกค้าของคนอื่น
- อาจเป็นการกระทำที่ผิดกฎ

**ทำยังไง:**
```
✓ Admin ตรวจสอบ Audit Logs
✓ ดูว่าเป็นการกระทำที่จำเป็นหรือไม่
✓ ถ้าไม่จำเป็นต้อง → ตักเตือนหรือลงโทษตามระเบียบ
✓ ถ้าจำเป็น (เช่น ช่วยเหลือ) → บันทึกเหตุผลไว้
```

---

### ❌ "ต้องการ Export Audit Logs ส่งธนาคารแห่งประเทศไทย"

**สาเหตุ:**
- ต้องส่งรายงานตามกฎหมาย
- ตรวจสอบจากหน่วยงานกำกับ

**ทำยังไง:**
```
✓ Admin เข้า Security Dashboard
✓ เลือกช่วงเวลาที่ต้องการ
✓ กด "Export Logs"
✓ เลือกรูปแบบ CSV หรือ PDF
✓ ส่งไฟล์ตามกระบวนการ
```

---

### ❌ "พบ Suspicious Activity ที่ยังเป็น PENDING"

**สาเหตุ:**
- ระบบตรวจพบพฤติกรรมน่าสงสัย
- ยังไม่ได้ตรวจสอบ

**ทำยังไง:**
```
✓ Admin เข้าไปดูรายละเอียด
✓ วิเคราะห์ว่าเป็นภัยจริงหรือ False Positive
✓ ถ้าไม่มีปัญหา → กด "FALSE_POSITIVE"
✓ ถ้ามีปัญหา → กด "INVESTIGATING" แล้วสืบสวน
✓ แก้ไขเสร็จ → กด "RESOLVED"
```

## สรุปง่ายๆ

### 🎯 จำไว้ 6 ข้อ

1. **5 ชั้นความปลอดภัย**: กำแพง → ยืนยันตัวตน → อนุญาต → ตรวจข้อมูล → บันทึก
2. **Audit Logs บันทึกทุกอย่าง**: ใคร ทำอะไร เมื่อไหร่ ที่ไหน
3. **Suspicious Activity**: ระบบตรวจจับอัตโนมัติ พฤติกรรมแปลกๆ
4. **4 ระดับความรุนแรง**: LOW → MEDIUM → HIGH → CRITICAL
5. **Velocity Check**: >50 ครั้ง/ชม. = ผิดปกติ
6. **Failed Login**: >5 ครั้ง = บล็อกชั่วคราว
