### Step 5: ไล่ตาม Controller → Service → Repository

**Controller:** `@/backend/src/modules/documents/controllers/document.controller.ts`

```typescript
async upload(request, reply) {
  const { file } = request.body;
  const customerId = request.body.customerId;
  
  // เรียก service
  const result = await documentService.upload(file, customerId, userId);
  
  return reply.send({ success: true, data: result });
}
```

**Service:** `@/backend/src/modules/documents/services/document.service.ts`

```typescript
async upload(file: Buffer, customerId: string, userId: string) {
  // 1. Validate file
  this.validateFile(file);
  
  // 2. Save to storage
  const filePath = await this.saveFile(file);
  
  // 3. Save to database
  const document = await documentRepository.create({
    fileName: file.originalname,
    filePath,
    customerId,
    uploadedBy: userId,
  });
  
  return document;
}
```

**Repository:** `@/backend/src/modules/documents/repositories/document.repository.ts`

```typescript
async create(data: CreateDocumentInput) {
  return prisma.document.create({
    data: {
      ...data,
      createdAt: new Date(),
    },
  });
}
```

**💡 Trick:** จำ pattern นี้:
```
Controller (รับ request)
    ↓
Service (business logic)
    ↓
Repository (database)
    ↓
Prisma (ORM)
    ↓
Database
```

### Step 6: ตรวจสอบ Database Schema

**หา Prisma schema:**
```bash
find backend/ -name "*.prisma" -type f
```

**เจอแล้ว:** `@/backend/prisma/schema.prisma`

```prisma
model Document {
  id           String   @id @default(uuid())
  fileName     String
  filePath     String
  fileSize     Int
  mimeType     String
  
  customerId   String?
  uploadedBy   String
  
  customer     Customer? @relation(fields: [customerId], references: [id])
  
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt
}
```

**💡 Trick:** ดู relation ด้วย (`@relation`) จะรู้ว่า table นี้เชื่อมกับ table ไหน

### Backend Pattern สำคัญ

```
Route (routes/index.ts)
    ↓
Middleware/PreHandler (auth, validation)
    ↓
Controller (รับ request, ส่ง response)
    ↓
Service (business logic, เรียกหลาย repository)
    ↓
Repository (query database แต่ละ table)
    ↓
Prisma Client
    ↓
PostgreSQL
```

## 🎯 สรุป: สูตรสำเร็จไล่โค้ด

```
1. START: หา Entry Point (UI หรือ API)
2. FOLLOW: ไล่ตามการเรียก function (Cmd+Click หรือ grep)
3. PATTERN: จำ pattern Controller → Service → Repository
4. CHECK: ดู type/interface ว่า data structure เป็นยังไง
5. VERIFY: ดู database schema ยืนยัน data model
6. DOCUMENT: จด flow ที่ค้นพบไว้ (ใช้ template ด้านบน)
```
